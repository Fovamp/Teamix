# Teamix 双模型协作 — 场景解读与敏感级声明

> 目标读者：架构师/开发者。讲"每个功能为什么存在、解决什么真实问题、如何亲自验证"，不贴代码。

## 一、双模型分工：谁在干哪类活

一次提问背后，系统会发起多次模型调用。用途标签（Purpose）就是给每次内部调用贴单子：

| 标签 | 系统在干什么 | 为什么归这个模型 |
|---|---|---|
| `execute` | 真正回答你的那次调用（你看到的回复） | 主对话，质量+窗口最重要 → **DeepSeek** |
| `plan` | agent 在心里列执行计划 | 计划很短 → Qwen |
| `subagent` | 派并行小兵查代码/日志 | 单任务短、一次好几个 → Qwen（省钱） |
| `classify` | 判断"这句话要不要触发能力/拦截" | 毫秒级高频 → Qwen |
| `cheap` | 其他高频廉价调用 | → Qwen |
| `guard` | 安全评审（审你的代码有没有漏洞） | 读你的全部上下文 → **强制 Qwen** |
| `compress` | 会话压缩/总结/长期记忆 | 把聊过的内容（含机密）浓缩 → **强制 Qwen** |

一句话：**你看到的回答质量由 DeepSeek 保底，系统背后跑腿的活全丢 Qwen**。guard/compress 是写死强制的，因为它们的对象天然敏感。

## 二、机密判定体系（数据源分类，非内容检测）

原则：**内容是什么不确定，数据从哪个来源来的确定**。所以系统不扫描内容语义，而是给"数据入口"分级。

### 敏感级 3 档（出网策略）

原则：**内容是什么不确定，数据从哪个来源来的确定**。所以系统不扫描内容语义，而是给"数据入口"定出网策略——只有三种行为：

| 档位 | 含义 | 出网行为 |
|---|---|---|
| `public` | 可出网（代码、公开文档） | 原文出网 |
| `redact` | 假名化后可出网（张三→客户甲） | 假名化副本出网，输出还原 |
| `internal` | 禁止出网（**默认档**，未声明即此档） | 强制内部模型 |

> 兼容说明：早期四档中的 `confidential`（机密）已并入 `internal`——两者的出网行为本来就完全相同（都强制内部）。保留 `confidential` 仅为兼容旧存储数据，前端已不提供该选项。

### 谁判断：三层分工

| 对象 | 谁判断 | 怎么判断 | 现状 |
|---|---|---|---|
| **文件工具**（read_file/grep/glob/ls 等） | 系统自动 | 参数路径命中机密清单 → **直接拦截该次调用**（不读取内容、不降级会话）；未命中 → public（代码默认出网） | ✅ 已实现 |
| **会话**（数据域钉住） | 系统自动 | MCP/skill/记忆声明 internal+ 或内容带标记 → 请求锁内部（不走文件工具拦截路径） | ✅ 已实现 |
| **MCP 服务器** | **你声明**（前端「设置→MCP」添加时选「数据敏感级」） | 未声明默认 **internal**（数据入口兜底） | ✅ 已实现 |
| **Skill** | **你声明**（前端「设置→Skills」添加时选） | 声明 internal+ 使会话初始即锁内部 | ✅ 已实现 |
| **记忆** | **你声明**（前端「设置→记忆」添加时选） | 同上 | ✅ 已实现 |
| **System Prompt 分级** | 系统自动 | InternalPromptMarker 机制存在但 serve 未接线 | ⚠️ 空挂（待接） |

### 机密黑名单（前端「设置→安全」可视化编辑）

```yaml
# .teamix/sensitive.yaml（前端保存，无需手改 config.yaml）
dirs: ["tenders/", "data/", "secrets/"]   # 机密目录（前缀匹配）
files: [".env", "*.pem"]                  # 机密文件（glob 匹配）
```

判定逻辑：AI 调用**文件类工具**（read_file/grep/glob/ls 等）时，检查参数里的 `path/dir/file/src/target` 是否命中清单：

- **命中 → 直接拦截该次调用**，返回「访问被拦截」提示（机密内容不进入上下文，会话不降级——本地窗口不被挤占）；
- 未命中 → 正常执行，结果标记 public（代码默认出网）；
- MCP 工具**不拦截**（其敏感级经声明走「内容可进上下文但锁内部」的数据域钉住路径）。

> 路由层另有纵深防御：请求里若仍出现机密路径的 tool call 参数，`scanToolArgs` 会强制内部（`tool_arg_sensitive_confidential`）。
> 配置经 `.teamix/sensitive.yaml` 独立文件保存，每次新会话/切模型热加载生效。

### 标记如何流动（本次新增的完整链路）

```
前端声明（MCP/skill/记忆 tab 下拉）
  → 存储：mcp.json sensitivity / SKILL.md frontmatter / memory .md frontmatter
  → 运行期：
      MCP 工具调用 → 结果消息带声明级（未声明 = internal）
      文件工具调用 → 结果消息带 public / confidential（自动）
      skill/记忆声明 → 会话初始敏感级（baseSensitivity，只升不降）
  → 请求级聚合（取最严档，只升不降）
  → 路由安全层：internal/confidential → 强制内部；redact → 假名化出网
```

## 三、关键机制逐项

### 假名化 + 闭环 Fail-Close
- 出网前：`张三→客户甲`、手机号→`PH1`、金额保量级（1200万→[约1亿]），本地上下文保持真实值。
- 回来后：输出还原为真实值，**校验无残留假名才写回**。
- 闭环：DeepSeek 幻觉出假名/改写占位符 → 整段丢弃 → 改由 Qwen 用真实值重新生成 → 审计记 `closed_loop_detected` 红色事故标记。

### 窗口预检（CJK 估算）
- 中文 1 字符 ≈ 0.75 token（按字符/4 会低估 3 倍爆窗），拉丁 ≈ 0.25。
- 超内部窗口且非机密 → 升级 DeepSeek；**机密内容在窗口预检之前就被安全层拦下，不存在"机密长文本因超窗裸奔出网"**。

### 故障降级（fail-closed）
- 路由层异常/无池 → 全部 Qwen，仅 public 出网，绝不裸奔。
- 外部故障重试 2 次（**仅非机密请求**）；机密/redact 禁止重试（防重复传输敏感数据）。
- 熔断 30s 冷却自动恢复；过载 `ErrPoolBusy`，forceInternal 请求过载时禁止降级外部（防泄露）。

### 配额与预算
- 个人日额 + 全局月额（architect 豁免），超限柔性降级 Qwen（用户无感）。
- 全局月额超限 → 预算降档全内部 + 一次性致命告警 `budget_exceeded`。

### 审计（泄露三信号）
- per-user × date JSONL（`.teamix/logs/ai-audit/<user>/<date>.jsonl`），仅 architect 可查。
- 三信号：①出网清单（`sent=true`）；②**非 public 却出网 = 事故**（红色+致命告警）；③闭环命中（假名化漏了）。

## 四、你有感的验证方式

1. **自检程序**（离线可跑，mock 池）：`go run ./cmd/teamix-selfcheck` → 32 项逐条打 ✓。
2. **真实服务终端日志**（回内网后）：`reasonix teamix --workspace <目录>`，每发一条消息终端打印
   `[Teamix] route decision ... pool=internal/external reason=...`——亲眼看到每次调用走向与原因。
3. **前端操作**：模型面板「仅本地模式」开关；「设置 → AI 审计」看出网清单/事故标记；
   **「设置 → MCP/Skills/记忆」新增的「数据敏感级」下拉**——选 internal/confidential 后，
   该数据源产生的内容从此走 Qwen（终端日志验证 `sensitive_forced_internal`）。

## 五、诚实声明（已知边界）

- 机密黑名单漏配 = 机密出网（代码默认出网是接受的风险，靠密钥正则兜底）。
- 假名识别依赖正则+字典，识别不到的换不掉；**金额量级/业务方向泄露不可消除**（1200万 vs 1300万）。
- 敏感长文档只能本地处理（质量降级，安全换的）。
- System Prompt 分级（InternalPromptMarker）机制存在但 serve 未接线。
- 手打机密文本无来源标记 → 默认放行（除非命中密钥模式）——数据源分类的固有取舍。
